What's eating your disk?

dush for Mac

Drop a folder, see what's big.

Drag one or more folders onto the window or onto the Dock icon, or press ⌘O. dush walks them in parallel and counts every file, hidden ones and app bundles included, while you watch the numbers climb.

  • Full Scan needs no folder. It checks the caches and temp folders that only hold stuff your Mac can rebuild: system and app caches, logs, the Trash, npm, Yarn, pnpm, Gradle, Cargo, Go, CocoaPods, Xcode's DerivedData and DeviceSupport, the simulator caches and VS Code's. Folders that aren't there or aren't safe are left out, and nested ones are counted once.
  • Downloads & Desktop scans the two usual suspects in one click.
  • Biggest so far: large files show up the moment they're found, folders as soon as they're measured. Press Esc to stop at any time.
  • Your options: a minimum size (100 MB, 512 MB, 1 GB, 5 GB or your own, like 1.5 GiB), files or folders only, skip node_modules, .git and other developer folders, or exclude names and patterns like *.xcarchive.

Safe to delete?

Ask your Mac, not a server.

Not sure what a folder is? Select it and ask. Apple Intelligence answers on this Mac, with a verdict, a one-line summary and what happens if you remove it. Then ask more, like Will I lose my SwiftUI previews?

dush tells the model only about the item:

  • always its path, name, size and whether it's a file or a folder;
  • if you like, how many items sit inside, the names and sizes of the 10 largest, and when it last changed;
  • never what's inside your files.

What it was told is shown under every answer. No server, no account, no key. Nothing leaves your Mac.

Developer Caches

Your tools rebuild most of this on their own.

dush knows where developer tools keep their caches and adds them up: 48.29 GB on a busy Mac. For each one it says what it is, whether it rebuilds itself or is worth a review first, and how to clear it the way that tool suggests. You do the clearing. dush runs nothing.

  • Xcode build cache

    Build files and indexes. Xcode rebuilds them on the next build.

    Rebuilds itself

  • Unavailable simulators

    Simulators whose OS version isn't installed anymore, with the apps and data on them.

    Review first

    xcrun simctl delete unavailable

  • Old device support

    Debug symbols for iOS and watchOS versions your devices no longer run. The newest version of each device is left out.

    Rebuilds itself

  • Stale node_modules

    Packages in projects nobody changed in 90+ days, in your code folders, never in Documents or Desktop.

    Review first

  • npm, pnpm and Yarn

    Packages your package managers downloaded. They download them again when a project needs them.

    Rebuilds itself

    pnpm store prune

  • Gradle and Homebrew

    Dependencies, build outputs, bottles and old versions of what you installed.

    Rebuilds itself

    brew cleanup

Every card has Show in Finder, which selects exactly the cache's folders, and Copy Command when the tool has one. Only the tools' own commands, to paste into Terminal yourself.

Our promises

dush only looks. It never deletes.

dush never deletes your files
It only looks. Removing something is always your call, in Finder or Terminal. The one thing dush can remove is its own scan history.
No tracking, no profiling
No analytics, no telemetry, no identifiers. Your scans never leave this Mac.
Offline, always
dush never uses the network. Apple Intelligence answers on this Mac, so nothing leaves it.
No accounts
No sign-in, no email, no cloud sync.
No in-app purchases
Free and open source. No subscriptions, no Pro version, no ads.

These aren't just words: the tests in each repository fail if the code ever reaches the network, deletes a file it doesn't own, or gets a delete button.

In the Terminal

The same engine, in your shell.

dush started as a command-line tool, and it still is one. The app and the CLI share the same engine, so they report the same sizes for the same folder, down to the byte. Install it with Homebrew:

brew tap andre_rori/tap https://codeberg.org/Andre_Rori/homebrew-tap.git && brew install andre_rori/tap/dush

Try it

# The caches and temp folders, no path needed
dush

# Your home, files over 1 GB, the top 10
dush ~ --min-size 1GB --files-only --top 10

# Skip node_modules, .git, DerivedData and friends
dush ~/Code --exclude-dev

# A report for your scripts
dush ~/Library/Developer --json > developer.json
